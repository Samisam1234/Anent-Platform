# agent-platform

Multi-module Java 21 / Spring Boot 3.4 AI agent platform: Ollama (local LLMs) + Gemini (Google AI Studio) + in-memory H2 by default (PostgreSQL/pgvector opt-in).

## Build & run

- No Maven wrapper — use system `mvn` (Java 21 required).
- From root: `mvn clean install`. All tests: `mvn test`.
- Single module: `mvn -pl <module> -am test` — `-am` builds sibling deps in-reactor (required on a fresh clone; modules depend on each other).
- Run the app: `mvn -pl ui spring-boot:run`, or launch `com.agentplatform.ui.AgentPlatformApplication` from an IDE. `ui` is the only bootable module (only it declares `spring-boot-maven-plugin`). No infrastructure is required to boot: the app defaults to in-memory H2 (`jdbc:h2:mem:agentdb` in `application.yml`). For PostgreSQL/pgvector run with `SPRING_PROFILES_ACTIVE=postgres` (after `docker compose up -d`).

## Infra (docker compose)

- postgres: `pgvector/pgvector:pg16`, db `agentdb`, `agent`/`agentpassword` on 5432. `init.sql` creates the `vector` extension + `memory` table only on first container init.
- ollama on 11434 powers chat + custom/process with dynamically selected local models. The Gemini API key is supplied via the `GEMINI_API_KEY` env var, referenced as `${GEMINI_API_KEY:}` in `application.yml` (gitignored — don't commit the key). The `:}` default means a missing key does NOT stop startup: the app boots and `GET /api/v1/ai/status` reports `configured:false`. Gemini is used only for resume parsing and the `ai/status` probe. Never log/expose the key and never return it from an endpoint.
- Gotcha: no datasource overrides in `main()` anymore — the database is defined entirely in `application.yml`: H2 in-memory by default (`spring.h2.console` at `/h2-console`), and the second `---` document activates a `postgres` profile (`SPRING_PROFILES_ACTIVE=postgres`, db `agentdb`, `agent`/`agentpassword`) that matches docker-compose + `init.sql`. Tables are created by `ddl-auto: update`. For local experiments the app also talks to a native `ollama` server on `localhost:11434` (enabled-then-crashed Docker isn't required for it).

## Architecture

- Module chain (build order): `tool-service` → `agent-core` → `memory-service` → `orchestrator` → `ui` → `logging` → `rag-service`. `logging` and `rag-service` are empty placeholders (starter-only poms, no sources). `memory-service` is real: `ConversationStore` interface + thread-safe `InMemoryConversationStore` (`@Service`), caps 60 msgs/conversation and 200 conversations (oldest evicted); no DB persistence yet (pgvector store can drop in behind the same interface).
- `ui` scans components, JPA repositories, and entities across the whole `com.agentplatform` root — new `@Entity` / `@Repository` / `@Service` anywhere is auto-discovered.
- Package naming is `com.agentplatform.<module>` except tool-service, which uses `com.agentplatform.tools`.
- Static web UI lives in `ui/src/main/resources/static` (plain HTML/JS).
- API (all under `/api/v1`): `agent/chat`, `ai/status`, `resume/upload` (multipart PDF → LLM-extracted profile), `jobs/search`, `jobs/match`, `custom/status`, `custom/process` (structured agent endpoint — `AgentRequest{prompt, taskType, model}` → `AgentProcessResponse` with per-`taskType` LangChain4j system prompts producing a `StructuredAgentResult`, plus `executionTimeMs`).
- Chat persistence: `POST /api/v1/agent/chat` takes `ChatRequest{query, conversationId?, model}` and returns `ChatResponse{response, conversationId}` (id generated when missing → always echoed). The orchestrator `AgentChatService.chatWithHistory(conversationId, systemPrompt, userMessage, model)` loads the stored transcript into the LangChain4j `ChatRequest`, appends the new turn, saves both to `ConversationStore` (nothing persisted on failure), returns `AgentChatResult{conversationId, response}`. The old stateless `chat(query)` / `chat(systemPrompt, query)` overloads are kept for `custom/process` and backward compatibility. Browser mirrors the thread in localStorage keys `agentplatform:conversationId` / `agentplatform:chatTranscript` (`app.js` restores transcript on load, "New conversation" button resets both + starts a fresh id).
- Dynamic Ollama model switching: `OllamaChatModelFactory` (`agent-core/config`) builds an `OllamaChatModel` per request from an optional `model` field — null/blank falls back to `ollama.default-model` (`qwen2.5:latest`, configurable via `ollama.base-url` / `ollama.default-model` in `application.yml`; base URL default `http://localhost:11434`). Chat and `custom/process` route through it (no more hardcoded Gemini chat model); Gemini remains wired only as the `GeminiChatModel` bean the resume parser + `ai/status` probe use. Both pages expose a model `<select id="modelSelector">` with the exact locally-pulled tags — `qwen2.5:latest` (Qwen 2.5 Code/Tools), `llama3.2:3b` (Llama 3.2 3B Fast Chat), `gemma3:4b` (Gemma 3 4B Reasoning); free-text model names are not supported by the UI. Selection persists in localStorage key `agentplatform:model` with a `#modelBadgeText` badge beside it, and a stale saved value silently falls back to the first option. First inference on a freshly pulled model is slow (cold CPU load) — and if a model isn't pulled, chat returns a classified 503 saying so (`ollama pull <model>`).
- Agent tools + code highlighting: `tool-service` (`com.agentplatform.tools`) provides `@Tool` beans — `ImageTools.generateImage(prompt)` (deterministic picsum URL, returns a raw `<div class="tool-image-result">…<img…>` HTML fragment), `EmailTools.sendEmail(recipient, subject, body)` (`JavaMailSender` bean from `MailConfig`, lazily creates a `JavaMailSenderImpl` with no host — sending without a configured SMTP just returns a failure string; `@Value` setter `tools.email.from`), `WhatsAppTools.sendWhatsAppMessage(phone, message)` (stub confirmation, phone `\+?\d{7,15}`). `AgentChatService` registers these on **every** model call via `ToolSpecifications.toolSpecificationsFrom`, executes tool calls in a bounded loop (`MAX_TOOL_ROUNDS=6`, `DefaultToolExecutor`, unknown-tool guard), and **"draw an image"-style prompts are short-circuited before any LLM call** by `ImageTools.isImageRequest()` (guarantees the `<img>` renders; prevents a model that never calls tools from producing no image). The image fragment is the only trusted raw-HTML the browser renders (whitelisted in `app.js renderAiContent`); all other assistant text stays escaped. `EmailTools`/`WhatsAppTools`/`MailConfig` are compiled into the app but any real send is call-driven (no scheduled background mail). Chat UI (Highlight.js 11.9.0 via cdnjs) turns fenced blocks into `<pre><code data-lang="…">` inside `.code-block` cards with a language label + "Copy Code" button (`app.js enhanceCodeBlocks` + `copyTextToClipboard`, `hljs.configure({ignoreUnescapedHTML:true})`).
- Gemini diagnostics & health check: `AgentChatService` and `ResumeProfileService` classify failures via `AiErrorClassifier` (`agent-core/ai`) — quota (`429`/RESOURCE_EXHAUSTED), auth (`401/403`, never leaks the key), model unavailable (`404`/NOT_FOUND), network — so error messages say what actually happened (e.g. free-tier quota hit) instead of "check your API key". It is provider-aware (`classify(error, provider)`); chat/custom failures are labeled "Ollama". `GET /api/v1/ai/status` (`AiStatusService` + `AiStatusController`) returns `AiStatusResponse{provider, configured, available, model, message, checkedAt}`: cheap on the plain GET (never calls Gemini), live one-shot probe only on `?probe=true` (8s cap, 60s cache). Don't auto-probe: the Gemini free tier is tiny (~20 content requests/day/model) and a status ping can exhaust it, which is the exact failure it explains.
- Resume matching is fully deterministic (`orchestrator/matching`: `JobMatchingService` + `EducationMatchingEngine`, weighted score, tie-break comparator, zero LLM calls). Weights are configurable via `agent.matching.*` (`JobMatchingConfig` `@ConfigurationProperties`; defaults 0.40 skills | 0.20 role | 0.15 experience | 0.10 track | 0.10 location | 0.05 education). Recommendation bands reuse the existing `RecommendationLevel` enum; each match carries `matchScore`, `strengths`, `concerns`, `educationScore`.
- `POST /api/v1/jobs/match` takes `JobMatchRequestDto` (`candidateProfileId` **or** inline `profile`; `jobs` optional else the deterministic search catalog, max 100; plus `keywords/location/experience/employmentType/limit/minScore/careerTrack`). It returns `JobMatchResponseDto` (`candidateProfileId`, `candidateName`, `totalJobs`, ranked `matches`, `source`, `live`, `message`). Missing stored profile → RFC 7807 404 (`CandidateProfileNotFoundException`).
- `resume/upload` persists the extracted profile (`CandidateProfilePersistenceService`) and returns its id in the `X-Candidate-Id` response header; the JSON body stays the plain `CandidateProfile`. On persist failure it logs and still returns 200 without the header. The Matches page reads that header via `localStorage` keys `agentplatform:candidateId` / `agentplatform:candidateName` (`matches.js` will only auto-fire when a candidate id is stored; candidate id = DB id, e.g. 1 after the first upload).

## Dependencies

- LangChain4j versions are intentionally mixed: core `1.0.0`, Google AI Gemini integration `1.0.0-beta5`, and the Ollama integration `1.0.0-beta5` (all pinned in root `dependencyManagement`; the Gemini and Ollama modules have no `1.0.0` GA and their GA series pull a newer core). Don't "fix" them to a single version.

## Testing

- No full `@SpringBootTest`. Tests are `@WebMvcTest` slice tests with mocked services, or plain JUnit (real in-memory PDFBox PDFs). No DB or external LLM required — preserve this so `mvn test` stays hermetic and fast.
- JPA repositories/entities are wired by `ui/PersistenceConfig` (`@EnableJpaRepositories` + `@EntityScan` over `com.agentplatform`), NOT by annotations on `AgentPlatformApplication` — putting them on the bootstrap class makes every `@WebMvcTest` fail to load (Spring Data registers a shared `EntityManagerFactory` the web slice can't satisfy).
- The Gemini chat model has a 60-second read timeout (`agent-core/GeminiConfig`); it's a remote cloud API, not local inference — don't remove the timeout.

## Conventions & gotchas

- Errors go through `GlobalExceptionHandler` as RFC 7807 `ProblemDetail` (`AgentChatException`→503, `IllegalArgumentException`→400). Exception to the convention: `JobMatchController` returns a plain `500` string its own catch block.
- Chat and `custom/process` hit Ollama (local models, `ollama.<base-url|default-model>`); resume parsing + `ai/status?probe=true` hit Gemini. Job search/matching are fully deterministic (`orchestrator/matching` engines, mock catalog from `MockJobSource` when no live `JobSource` is wired).
- No CI and no root `.gitignore` until recently: each module has its own (e.g. `ui/.gitignore` ignores `/target/` and `src/main/resources/application.yml`), plus a root `.gitignore` for `.env`. `.github/` contains untracked "modernize" leftovers, not workflows.
